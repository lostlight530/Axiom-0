## 1. 做了什么：Anthropic 的“大脑与双手”解耦 / What Was Done: Anthropic's Decoupling of "Brain and Hands"

> **[CN]**: 面对模型能力迭代（如从 Claude 3.5 Sonnet 到 4.5 Opus）导致的旧代理线束（harnesses）失效问题，Anthropic 推出了 Managed Agents 托管服务,
>
> **[EN]**: Facing the deprecation of old agent harnesses caused by model capability iterations (e.g., from Claude 3.5 Sonnet to 4.5 Opus), Anthropic launched the Managed Agents hosted service.

### 1.1 大脑-双手-会话 架构 (Brain-Hands-Session Architecture)
- **概念 (Concept)**:
  > **[CN]**: Anthropic 试图效仿经典操作系统的抽象层设计（如进程、文件系统），构建出独立于底层模型的标准 API 接口,它将代理工作流切分为负责逻辑规划的“大脑”、负责环境交互的“双手”，以及维持状态的“会话”，试图将大模型作为可随时插拔的引擎,
  > **[EN]**: Anthropic attempts to emulate the abstraction layer design of classic operating systems (like processes and file systems) to build standard API interfaces independent of the underlying models. It slices the agent workflow into a "brain" for logical planning, "hands" for environmental interaction, and a "session" to maintain state, attempting to treat LLMs as plug-and-play engines.

- **应对“上下文焦虑”与幻觉漂移 (Coping with "Context Anxiety" and Hallucination Drift)**:
  > **[CN]**: 随着模型上下文窗口的激增，模型常常表现出提前结束任务的“上下文焦虑”行为,Anthropic 发现每次模型更新都会破坏原有的工程预设，因此他们试图建立一个稳定的中间层，用传统软件工程的静态框架去容纳概率模型的动态混乱,
  > **[EN]**: As model context windows surged, models often exhibited "context anxiety" by terminating tasks prematurely. Anthropic discovered that every model update broke original engineering presets, so they attempted to build a stable middle layer, using the static frameworks of traditional software engineering to contain the dynamic chaos of probabilistic models.
