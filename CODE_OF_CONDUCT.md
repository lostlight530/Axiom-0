# Code of Conduct


## Our standard

Contributors must engage respectfully, critique claims and artifacts rather than people, disclose uncertainty, and protect private or security-sensitive information. Harassment, threats, discrimination, doxxing, deliberate deception, and repeated disruption are unacceptable in repository spaces.

### 中文证据与行为要求 / Evidence-aware collaboration

对协议、数学差异、科研发表和 Agents 合作的判断必须说明输入范围、原始状态及实际检查；一次 D_KL=0、扫描通过或 GitHub 合并不能被宣传成普遍正确性或经过外部认证

Claims about protocols, mathematical divergence, research publications and Agent collaboration must identify input bounds, original state and executed checks. D_KL=0 on a fixture, a passing scanner or a merged PR is not universal correctness or third-party certification

## Evidence-aware collaboration

Technical disagreement is welcome. Distinguish observed results, sourced facts, design proposals, and hypotheses. Reproducible counterexamples may overturn project language; status or confidence does not exempt a claim from review.

## Enforcement

Report conduct concerns privately through the repository owner’s GitHub profile contact route. Maintainers should acknowledge reports, minimize collection of personal data, avoid conflicts of interest, and apply proportionate actions: clarification, warning, temporary restriction, or removal. Security vulnerabilities belong in the private process described by `SECURITY.md`, not public issues.

This policy applies to repository issues, pull requests, discussions, reviews, and project-representative interactions.
